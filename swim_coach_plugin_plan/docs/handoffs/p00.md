  em host remoto.

## Riscos/limitações restantes

- Auth0 DCR pode estar desabilitado no tenant; CIMD ou cliente pré-registrado
  continuam opções válidas conforme os metadados reais.
- `python-garminconnect` é não oficial e pode quebrar com mudanças do Garmin.
- Um tunnel temporário não substitui a URL HTTPS estável exigida pelo produto.
- A instalação atual do plugin é Skills-only e não invoca o MCP por uma conexão
  hospedada; a conexão project-scoped testada pertence ao Codex local.
- O remote GitHub responde por SSH; commit `2faaf62`, PR #1 e CI remota verde
  comprovam publicação e execução em clone limpo.
- `codex mcp list` revelou que outro MCP global preexistente guarda uma credencial
  estática nos argumentos do processo. O valor não foi copiado; ele deve ser
  rotacionado e migrado para uma variável de ambiente antes de novos logs.

## Próxima ação recomendada

1. Criar um Secure MCP Tunnel no Platform (requer `tunnel_id`, API key de runtime
   e permissões) ou publicar uma URL HTTPS segura para `/mcp/` e os metadados OAuth.
2. Executar `probe_oauth_metadata.py` contra o tenant real e guardar somente a
   saída sanitizada.
3. No terminal local do proprietário, executar `probe_garmin_read.py`; não
   fornecer credenciais à LLM.
4. Registrar a conexão MCP hospedada, gerar `.app.json` apenas com o ID retornado
   e repetir `get_capabilities` na superfície remota suportada.
5. Após as três provas externas restantes, atualizar o checkpoint e reavaliar o gate P00.
